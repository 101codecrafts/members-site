# r11/profile research: account menus, settings and profile sharing (5 Nov 2026)

Common pattern: a menu head card (who you are) → your stuff (profile, plan) → money → settings, help, appearance and language → switch account → sign out last, set apart. Danger actions sit only in settings, never in the menu.

## Standards used
- **Clerk** (our auth): the frontend `User` object has `setProfileImage({file})`, `updatePassword`, `createTOTP`/`verifyTOTP`/`disableTOTP` and `getSessions()` (each `SessionWithActivities` has `revoke()`) ([docs](https://clerk.com/docs/js-frontend/reference/objects/user)). `Clerk.openUserProfile()` opens Clerk's own secure panel for password, 2FA and passkeys. We use it for these instead of re-implementing them.
- **Reverification for sensitive actions**: Clerk's server-side `auth().has({ reverification: … })` checks that the user verified their credentials recently (10 min by default) ([guide](https://clerk.com/docs/guides/secure/reverification), [auth object](https://clerk.com/docs/reference/backend/types/auth-object)). The backend erase request now requires it.
- **Web Share API Level 2**: test `navigator.canShare({files})` first, then `navigator.share({files:[new File([blob],'x.png',{type:'image/png'})]})`. It needs HTTPS and a user gesture. Fall back to download ([MDN](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/canShare), [web.dev](https://web.dev/patterns/files/share-files)).
- **Open Graph**: a public profile link `/u/<handle>` unfurls with og:title, og:description and og:image (1200×630) on WhatsApp, LinkedIn and X. The static host can't render per-user OG images, so the link uses the site OG image for now. A per-user OG image endpoint is an open item for the backend.
- **Uganda Data Protection and Privacy Act 2019**: right of access (data export, already in `GET /api/v1/me/export`), right to erasure (queued `data_requests` with a 24 h cool-off), and children's data needs a parent or guardian's consent (s.8). This drives the Guardian section and the delete flow.
- **WCAG 2.2**: the menu follows the APG menu-button pattern (already in js/shell.js). Targets are ≥44px. `prefers-reduced-motion` and the `cc_bg_motion` setting are honoured.

## Decisions
1. The menu is built at build time (no layout shift). js/account.js only fills in the user, plan and role and hides rows the role can't use (payouts: tutors only).
2. Settings is one page, `settings.html`, with a sticky section nav (the GitHub/Discord model), rather than ten pages, so it works offline and on 2G. Every section has a deep-link anchor.
3. Share as an image reuses the card.html canvas look: navy, hard offset shadow, Archivo Black. Share as a PDF is generated client-side with no library: the PDF is written by hand with built-in Helvetica plus an embedded JPEG of the brand header. It stays under 100 KB and needs no CDN.
